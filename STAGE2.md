# Stage 2 implementation

This is the stage 2 React and Vite app for `data/heart_rate_week.csv`.

## Run locally

Open Git Bash in this project folder and run:

```bash
bash run_app.sh
```

The script installs the pinned dependencies if `node_modules/` is missing, then starts Vite.
Open the Local address Vite prints, usually `http://127.0.0.1:5173/`. Stop with Ctrl+C.
Node.js 20.19+ or 22.12+ is required by the pinned Vite version; Node.js 24 is suitable.
An internet connection is needed for the first dependency installation.

## What to check in the app

- The timeline displays the full recorded week on an actual timestamp axis.
- All recorded minutes appear in gray. Blue outlined circles identify the temporary sample.
- Amber bands mark intervals without a recording; lines stop at gaps. Expand Recording gaps
  to inspect exact intervals when a gap is too narrow to distinguish at week scale.
- The temporary sample has 100 distinct rows, selected by simple random sampling without replacement.
- The current seed is displayed. Applying the same seed reproduces the same sample.
- The true population mean and the single sample mean are separately labelled in bpm.
- Expand Inspect the 100 sampled rows to check the selected records.
- On narrow screens, scroll horizontally within the chart to inspect its full width.

This stage contains one temporary sample, not the repeated-sampling investigation.
Other sampling methods and later-stage experiments have not been added.

## Technical verification

Run `npm test`, or `node --test tests/sampling.test.js` before dependencies are installed.
Six automated checks cover known-answer means on synthetic data, valid sample sizes,
distinct selected rows, preservation of source rows, reproducibility, random-number bounds,
timestamp parsing, gap segmentation and real CSV parsing. No investigation findings are reported.

The original data and `DECISIONS.md` are unchanged. All sampling and estimator calculations
implemented for this stage are in `src/sampling.js`.

Dependency installation and browser rendering still require verification on the student's
computer: the authoring session could not reach the npm registry. A dependency lockfile
must be generated by the first successful `npm install`, retained with the project and
committed with source code when the project is placed under git.
